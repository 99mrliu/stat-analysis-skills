# 缺失值规则（missingness rules）

## 缺失标记清单（本 Skill 识别）

空串、`NA`、`N/A`、`NaN`/`nan`、`null`、`None`、`-`、`.`、`?`、`缺失`（大小写不敏感，NFKC 归一化后比较）。
注意：`.` 与 `-` 在某些数据里是合法文本，因此只在"整格等于该标记"时判缺失，子串不算。

## MCAR / MAR / MNAR 区分

- **MCAR**（完全随机缺失）：缺失与任何已观测/未观测变量无关。后果最小，仅损失样本量。
- **MAR**（随机缺失）：缺失可由已观测变量解释（如高龄组更常缺血压）。可用以观测变量为条件的插补或加权校正。
- **MNAR**（非随机缺失）：缺失与缺失值本身有关（如重症者更常失访）。任何基于已观测数据的修正都有偏，需敏感性分析。

本 Skill 只做**启发式提示**：比较"某列缺失行"与"非缺失行"在其他数值列上的均值，若相差超过 1 个标准差则记录"缺失或非随机"提示。**不做正式检验**（如 Little's test），正式判断属推断阶段。

## 处置策略

### report_and_exclude（默认）

- 缺失值原样保留；每个统计量使用该变量的有效 n，并在报告中同时给出 n_valid 与 missing_pct。
- 适用：缺失率低、机制不明、样本量充足；也是一切审计的最低诚实基线。

### 插补（impute，仅在被明确指示时）

- 本 Skill **从不静默插补**。仅当 case.json `missing_policy` 以 `impute` 开头或 task.md 明确要求时，在账本中记录"交由分析阶段执行并加 flag 列"。
- 可辩护条件（缺一不可）：缺失机制可论证为 MCAR/MAR；缺失率不过高（经验阈值：列缺失 <5% 均值/中位数插补尚可接受，5–20% 建议多重插补，>20% 插补结论须作敏感性分析）；插补值必须可追踪（额外 flag 列）。
- 被插补的行参与推断时必须能一键剔除复核。

### drop_rows（整行删除）

- 仅当 case.json `missing_policy: drop_rows` 时执行；否则不删。
- 风险：MAR/MNAR 下 complete-case 分析有偏；样本量与统计功效下降。

## 报告要求

- 每列 missing_count / missing_pct；每行缺失数；最高频缺失模式（哪些列一起缺、各多少行）。
- 任何策略变更必须落清洗账本：rule_id、condition、action、rows_affected、before/after。
